# Privacy Consent Dialog

The consent dialog is rendered via a Twig template included in your theme's layout. This page covers the template variables available, how to structure the HTML, and what the JavaScript layer expects.

For how the consent signals work with Google Tag Manager and how to read consent in PHP, see the [Consent Dialog module guide](../05.%20module%20guide/29.%20consent_dialog.md).

---

## Template variables

The following global variables are available in all frontend templates when the consent dialog is enabled:

| Variable | Type | Description |
|---|---|---|
| `privacyConsentEnabled` | bool | `true` when the dialog is switched on in Settings |
| `privacyConsentDialogShow` | bool | `true` when the visitor has not yet stored their preferences |
| `privacyConsentDialogLevels` | array | The configured consent levels (see below) |

### `privacyConsentDialogLevels` structure

Each entry in the array is an object with two keys:

```twig
{
  name: 'analytics_storage',      {# the raw level identifier used in cookies and gtag() #}
  localeKey: 'AnalyticsStorage'   {# PascalCase key used to build translation keys #}
}
```

The `localeKey` is derived by converting the snake_case level name to PascalCase:
`ad_storage` → `AdStorage`, `analytics_storage` → `AnalyticsStorage`, etc.

Use `level.name` as the `data-value` attribute on checkboxes so the JavaScript can read it, and `level.localeKey` to construct translation keys:

```twig
{{ ('msg.PrivacyConsentLevel' ~ level.localeKey ~ 'Title')|trans|raw }}
{{ ('msg.PrivacyConsentLevel' ~ level.localeKey ~ 'Text')|trans|raw }}
```

## Required HTML structure

The JavaScript layer (`jsFrontend.consentDialog`) works by looking for specific `data-role` attributes. The following roles must be present if you use a given feature:

| `data-role` | Element | Purpose |
|---|---|---|
| `privacy_consent_dialog` | The modal wrapper | Required. The dialog container. |
| `privacy_consent_dialog_form` | `<form>` inside the dialog | Required. Wraps all checkboxes. |
| `privacy_consent_dialog_save_button` | Submit button | Required. Saves the current checkbox state. |
| `privacy_consent_info` | A separate info bar | Optional. Shown before the dialog opens. |
| `privacy_consent_info_save_button` | Button in info bar | Optional. Accepts all levels at once. |
| `privacy_consent_info_preferences_button` | Link in info bar | Optional. Opens the dialog. |
| `privacy_consent_dialog_necessary_button` | Link in dialog | Optional. Accepts only functional cookies. |

Each checkbox must have:
- `data-role="privacy-level"`
- `data-value="{{ level.name }}"` (e.g. `analytics_storage`)

### Functional cookies checkbox

The functional level (`functionality_storage`) is always granted and must be rendered as a disabled, pre-checked checkbox. It should **not** be in the `{% for level in privacyConsentDialogLevels %}` loop — it's hardcoded:

```twig
<input type="checkbox" checked disabled
       data-role="privacy-level"
       data-value="functionality_storage"
>
```

## Minimal template example

```twig
{% if privacyConsentEnabled and privacyConsentDialogShow %}
  <div data-role="privacy_consent_dialog">
    <form data-role="privacy_consent_dialog_form">

      {# Functional — always on, not configurable #}
      <label>
        <input type="checkbox" checked disabled
               data-role="privacy-level"
               data-value="functionality_storage">
        {{ 'msg.PrivacyConsentLevelFunctionalityStorageTitle'|trans|raw }}
      </label>

      {# Configurable levels #}
      {% for level in privacyConsentDialogLevels %}
        <label>
          <input type="checkbox"
                 data-role="privacy-level"
                 data-value="{{ level.name }}">
          {{ ('msg.PrivacyConsentLevel' ~ level.localeKey ~ 'Title')|trans|raw }}
        </label>
      {% endfor %}

      <button type="submit" data-role="privacy_consent_dialog_save_button">
        {{ 'msg.PrivacyConsentDialogSave'|trans }}
      </button>

    </form>
  </div>
{% endif %}
```

For a full Bootstrap 5 implementation including the info bar, accordion layout, and necessary-only button, refer to `src/Frontend/Themes/Siesqo/src/Layout/Templates/PrivacyConsentDialog.html.twig`.

## Translation keys

The following frontend Core locale keys are available for the consent dialog:

| Key | Purpose |
|---|---|
| `msg.PrivacyConsentInfoTitle` | Heading of the info bar |
| `msg.PrivacyConsentInfoBody` | Body text of the info bar |
| `msg.PrivacyConsentInfoSettings` | "Your preferences" link label |
| `msg.PrivacyConsentInfoSaveAll` | "Accept cookies" button label |
| `msg.PrivacyConsentDialogTitle` | Modal heading |
| `msg.PrivacyConsentDialogBody` | Intro text inside the modal |
| `msg.PrivacyConsentDialogAcceptNecessary` | "Only necessary" link label |
| `msg.PrivacyConsentDialogSave` | Save button label |
| `msg.PrivacyConsentLevelFunctionalityStorageTitle` | Title for functional level |
| `msg.PrivacyConsentLevelFunctionalityStorageText` | Description for functional level |
| `msg.PrivacyConsentLevel{LocaleKey}Title` | Title for each configurable level |
| `msg.PrivacyConsentLevel{LocaleKey}Text` | Description for each configurable level |

Available `{LocaleKey}` values: `AdStorage`, `AdUserData`, `AdPersonalization`, `AnalyticsStorage`, `PersonalizationStorage`, `SecurityStorage`.
